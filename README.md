# CueRelay

当前版本：2.13

Windows 本地的 Codex 工具箱：把常用提示词存成片段、一键发出去，按计划执行任务，扫描并切换对话，开关 Codex 与代理。常驻托盘，Ctrl+Alt+K 随时唤出。所有动作都先识别界面、再校验结果。

不需要安装任何第三方 Python 库，只要有 Python 3.10+。

## 启动

双击 `启动_CueRelay.cmd`。

命令行：

```
python cuerelay.py           启动界面
python cuerelay.py --check   运行无界面自检（识别算法、调度、数据迁移）
python cuerelay.py --version 显示版本
```

## 界面

左侧六个视图：任务、片段、对话、应用、日志、设置。

- **任务**：左侧列表按状态分成「进行中 / 失败 / 已停止」三组，点分组标题可以折叠，其中「已停止」默认收起——几十条做完的旧任务不应该一打开就铺满屏幕。列表顶部可搜索。右键任意任务可以暂停/启用、立即运行、复制一份或删除，不需要先载入编辑器。打开窗口时会自动选中第一个任务，右侧编辑区一屏写完整条流程（提示词 → 计划 → 发送方式 → 目标对话），底部只有两个动作：次要的「保存」和主要的「立即执行」。
- **片段**：常用提示词存成一条条片段，按使用次数排序。选中后可以「发送」（立刻发到当前对话）、「填入任务」（变成一条新任务草稿，再定计划）或直接编辑。片段是工具箱里最常用的东西，所以它自己占一页。
- **对话**：直接读 Codex 自己的本地数据库，按项目分组列出全部对话（含没有项目的），
  可以搜索、筛选、折叠分组、看详情，点「在 Codex 打开」切过去。子代理对话默认隐藏。
- **应用**：Codex 与 v2rayN 各一张卡，直接显示「运行中 / 在后台 / 未运行」和它的启动目标，右边是启动与关闭。下面是「一键启动：v2rayN → Codex」和两个建定时开关任务的按钮。
- **日志**：「运行日志」按级别筛选、带时间戳，可直接打开日志文件；「执行记录」是每条任务每次执行的结果、耗时和错误，重试的会标明是第几次。
- **设置**：目标应用关键词、识别与校准、执行间隔与补执行窗口、启动与代理、开机自启与全局热键、托盘与关闭、主题与置顶、数据位置。

任何视图里按 **Ctrl+K** 打开命令面板：打字过滤，上下键选择，回车执行。切视图、跑任务、发片段、跳对话、开关 Codex 都在里面。

| 快捷键 | 作用 |
| --- | --- |
| Ctrl+K | 命令面板（再按一次收起） |
| Ctrl+Alt+K | 全局：在任何程序里唤出窗口并打开命令面板 |
| Ctrl+N | 新建（任务页新建任务，片段页新建片段） |
| Ctrl+S | 保存（按当前页分派） |
| Ctrl+Enter | 执行（任务页立即执行，片段页立即发送） |

主题有浅色与深色两套，标题栏会跟随主题一起切换（Windows 10 1809 及以上）。所有尺寸按系统 DPI 缩放，125%/150%/200% 缩放下文字不会被位图拉伸。

## 执行时的浮层

每次执行都会在目标窗口上盖一层透明、鼠标可穿透的浮层。它把过程拆成三种一眼能分开的状态——「还在找」「认准了」「走到哪一步」——而不是一律画一个框：

- **扫描**：还没认出来的时候先标出"正在这一块里找"。四条很淡的角标圈出范围，一道光带左右扫，标签是一个转着圈的「查找搜索框」。刻意不画实框：实框是"认准了"的语言，混着用会让人以为它已经把范围认错了。
- **锁定**：认出来之后角标从外面收拢到元素上，落定那一下角标亮到发白、外面推开一圈亮边，标签才浮出来（`输入框 · 识别 · 710×90`）。这一下闪是"刚认出来的"唯一的正向回执——没有它，框只是出现在那里，分不清是刚认的还是上一轮留下的。
- **换目标**：旧框直接过渡到新框，不重播收拢；只有"新认出来"才闪。
- **进度卡**：贴着当前那个框放（下面放不下就换到上面），写这一步在做什么、第几步 / 共几步、以及一条带刻度的进度条；换一句话时卡片轻轻浮一下。左侧色条标出这一步是正常（蓝）、在等（黄）还是停了（红）。发送按钮这种套在输入框里的小方块，卡片会跟着外层那个输入框走，不会被挤到窗口角上。
- **标记**：小图标（放大镜、发送按钮）的标签放在图标右侧，右边放不下就挪到左边——图标本身只有几十像素，标签压上去等于把它盖掉，而"框的是哪个图标"恰恰是这时候唯一要看的东西。
- **点击回执**：每次点击都在落点画一圈扩散的涟漪。
- **失败也留回执**：出错时卡片变红、写明为什么停，停 0.9 秒再撤浮层。否则浮层"啪"地消失，用户分不清是成功了还是断在了哪一步。

框线画在元素外侧、角标只占每条边最外侧一小段，所以浮层本身不会盖住它正在描述的像素。浮层完全穿透鼠标，不影响自动化自己的点击。设置里可以关掉（「执行时显示识别框线」）。

**浮层会把自己画进截图里**——这是它唯一的副作用，也踩过坑：角标收拢、落定的闪、点击的涟漪，每一个都会让"这块像素变了"成立，哪怕应用本身什么都没做。所以取像素基线之前、开始比对之前，都会先等这段动画过去（`OVERLAY_SETTLE` / `OVERLAY_PULSE`）。不做这件事，"粘贴校验"和"发送校验"就会把自己的动画当成应用的响应，明明没发出去也可能判成发了。

## 应用与代理

CueRelay 需要 Codex 在前台才能发消息，所以它自己管这两件事：把 Codex 拉起来、把代理先弄起来。「应用」页就是这两件事的开关面板。

- **Codex 是 MSIX 包，不能按 exe 路径启动**（`WindowsApps` 目录受保护）。CueRelay 从进程的安装路径反推包族名（`OpenAI.Codex_26.1029.7803.0_x64__2p2nqsd0c76g0` → `OpenAI.Codex_2p2nqsd0c76g0`），再用 `shell:AppsFolder\…!App` 拉起，不需要额外查询包清单。
- **窗口在托盘里就直接恢复，不重新启动**。Electron 应用点关闭往往只是收进托盘，进程还在，句柄也还在。这种情况下 `ShowWindow` + `SW_RESTORE` 约 0.04 秒回到前台；冷启动约 2.8 秒。已经存在窗口时不会再启动第二个实例。
- **关闭是真的退出**。先发 `WM_CLOSE`，进程还在就逐个 `TerminateProcess`，并等它们消失。只用 `WM_CLOSE` 会把 Codex 关进托盘，进程继续占着内存。
- **v2rayN 自动绑定**。按「运行中的进程 → 卸载表 → 常见目录 → 非系统盘浅扫」的顺序找 `v2rayN.exe`，启动时自动写进设置，找不到就安静跳过，也可以手填路径。以管理员身份运行时普通权限读不到进程路径，所以不能只靠进程表。
- **先代理再 Codex**。设置里的「启动 Codex 前先确保 v2rayN 已运行」默认开启：Codex 启动时连不上会停在错误页，之后要用户手动刷新。v2rayN 需要管理员权限时会弹一次 UAC，CueRelay 只等到进程出现，不去等窗口。
- **执行前自动拉起目标应用**。每次执行任务前先找目标窗口；没开就按设置把它拉起来，收进托盘就恢复，然后才继续识别与发送。这条默认开启，关掉后找不到窗口会直接报错停下。
- **开机自启**。设置里的「开机自动启动 CueRelay」写的是 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的一个值，用的是 `pythonw.exe`——用 `python.exe` 每次开机都会多一个黑色控制台窗口，而这个程序本来就不需要控制台。写入失败（比如被组策略挡住）会把开关拨回去并说明原因，不会留下一个看起来开着、实际没生效的状态。

「定时开关」把这两件事接进了调度器：任务类型除了「发送提示词」，还有「启动应用」和「关闭应用」，它们不需要提示词、发送方式和目标对话，编辑器里这几组会整块收起。从「应用」页的两个按钮可以直接建好一条每天执行的开关任务，时间自己改。

## 片段与对话

**片段**是一段存下来的提示词。它有三个出口：

- 「发送」立刻发给当前对话（如果当前正在生成回答，会先等它结束）；
- 「填入任务」变成一条新任务草稿，计划时间由你定；
- Ctrl+K 里直接打片段名，也能发。

列表按使用次数排序，常用的自然浮到上面。名称为空时取内容开头，不会出现一排「未命名片段」。

**对话**页读的是 Codex 自己的数据库，不是侧边栏。这件事值得单独说明，因为它决定了
这一页能看到什么：

- **数据在 `~/.codex/state_*.sqlite`**。`threads` 表里每行是一条对话：标题、工作目录、
  创建/更新时间、模型、token、归档状态、来源。正文轮次在 `thread_history_*.sqlite`。
  读一次 966 条大约 70 毫秒，所以进页面就自动读一次，不用点按钮。
- **项目归属按目录算**。这一版 Codex 的 `threads.project_id` 全是 NULL，真正的归属
  关系在 `project_roots` 表里：拿 `cwd` 去匹配项目根，**取最长前缀**。所以
  `E:\aitools\helloalp_web\src` 归 `helloalp_web`，不会归到父目录 `E:\aitools`。
  匹配不上任何项目根的才是「无项目」——`Documents\Codex\2026-07-10\sa` 这种。
- **子代理默认不显示**。本机 966 条里 577 条是子代理，全铺出来对话页就变成日志页了。
  顶部有一个「子代理」开关。
- **库开着也能读**。Codex 一边聊一边写，WAL 里可能还有没合并的页。先试只读连接，
  失败就把库文件（连 `-wal`/`-shm`）复制到临时目录再读。
- **没有 state 库也能用**。纯 CLI 用户的记录在 `sessions/**/rollout-*.jsonl`，
  回退去解析那边的 `session_meta` 和第一条用户消息。

切换仍然走已经验证过的那条链路：搜索标题 → 点结果 → 核对消息区顶部的标题，
对不上就报错。本地库只负责「告诉我们要找哪一个」，不负责「怎么点」。

## 2.13 做了什么

2.13 只做一件事：**把"操作一下就闪一下"从根上关掉**。

用户的原话是"UI 频闪很厉害，操作一下就闪烁一下"。查下来不是显卡、不是主题、
也不是动画太多，是**每次交互都把控件销毁重建**：任务列表每敲一个字，先把整列
`destroy()` 再按新结果建一遍；对话页每点一行，右边详情整页重建。Tk 在 Windows
上不做双缓冲，销毁和重建之间那一下会露出父容器的底色——就是那一下闪。

先把"到底闪不闪"量出来，不然改完也只能靠感觉。`tools/probe_chats_flicker.py`
用后台线程连续抓真实屏幕（60 帧/秒），把每一帧和"稳定后的最终画面"逐点比色差。
两个坑都是量的时候踩出来的：

- **抓帧不能放在 `after` 里**。Tk 回调是阻塞的，`after` 排在回调后面，抓不到回调
  中间的画面——而闪的那一下正好在回调里。得放在另一个线程里跑 BitBlt。
- **主线程绝对不能 `sleep`**。`time.sleep` 不处理 Tk 事件，窗口根本不会重画，
  抓到的是一张冻住的旧画面，看上去"没有闪"，其实是没量到。

量出来之后是三处改动：

- **任务列表、片段列表换成控件池**。控件只建一次，之后 `grid()` 换位置、
  `configure()` 换文字，切筛选和搜索不再销毁任何东西。实测筛选一次的回调从
  34.5 ms 降到 10.5 ms，清空搜索 5.9 ms，且交互期间新建控件数为 0。
- **详情页不再强制同步排版**。`show()` 里原来有一句 `update_idletasks()` 加一次
  `_rewrap()`，为的是拿到宽度重算折行；但折行宽度只跟宽度有关，内容变了宽度没变。
  这一句每次要 80 毫秒，而这 80 毫秒里窗口是画不出来的。改成由 `body` 的
  `<Configure>` 驱动，切一次筛选从 115 ms 降到 31 ms，点一行从 17 ms 降到 6 ms。
- **收起时只动该动的那些**。`grid_remove()` 每次都会让 Tk 重算几何，对已经藏起来
  的控件再喊一次是白花钱。记住当前真正挂在布局里的控件，只对"上一轮还露着"的
  动手。

顺带修掉一个一直在的视觉缺陷：`_finish_render` 里那次 `update_idletasks()` 被
换成 `after_idle`，选中竖杠等这一帧排完再放位置；`_place_indicator()` 每次
`lift()` 一下，池子复用之后竖杠不会被后来的行盖住。

验收方式是可重复的：`tools/probe_chats_flicker.py` 跑一遍，看峰值色差有没有超过
静止基线；`tools/probe_tasks_ui.py` 19 项、`tools/probe_chats_ui.py` 17 项
交互自检全过；`cuerelay.py --check` 56 项全过。

## 2.12 做了什么

2.12 只做一件事：**对话页不再看屏幕，改成读 Codex 自己的数据库**。

先说清楚 2.11 那版为什么"形同虚设、点了没反应"。它根本没跑起来：
`run_exclusive(work, label)` 调用的是 `work()`，而那段代码写成了 `work(toolbox)`，
一点就抛 `missing 1 required positional argument`。异常被调度器吞进日志，
界面上只剩一句「正在读取…」永远不动。`cuerelay.log` 里能翻到三行一模一样的报错。

就算修掉这个签名，那条路也走不通：截屏 + OCR 读侧边栏，要窗口在前台、侧边栏
展开、列表滚六屏，读到的还只是滚过的那几屏。所以这次不是修，是换。

- **数据源换成 SQLite**。一次读完 966 条 70 毫秒，标题、目录、时间、模型、token、
  轮次、归档状态一次拿全。不用滚列表、不用 OCR、不要求窗口在前台。
- **项目归属按目录算**。这一版 Codex 的 `threads.project_id` 全是 NULL，真正的
  归属关系在 `project_roots` 里：拿 `cwd` 匹配项目根，取最长前缀。匹配不上的
  才是「无项目」。
- **子代理默认不显示**。本机 966 条里 577 条是子代理，全铺出来对话页就变成
  日志页了。顶部一个「子代理」开关，要看再打开。
- **库开着也能读**。先试只读连接，失败就把库文件连 `-wal`/`-shm` 一起复制到临时
  目录再读。读不了就明确报错，不能假装"没有对话"。
- **列名不写死**。`threads` 有 38 列而且随版本变，SELECT 按"有就用、没有就跳过"
  拼出来，少一列不会让整页崩掉。
- **没有 state 库也能用**。纯 CLI 用户的记录在 `sessions/**/rollout-*.jsonl`，
  回退解析那边的 `session_meta` 和第一条用户消息。

界面这一版才开始像一个浏览器：

- 左边是分组目录（置顶 / 项目 / 无项目 / 归档），组头能折叠，条数写在组名后面；
- 一行是搜索（标题、项目、目录、ID 都能搜）加筛选胶囊，选中的那块底色会滑过去；
- 右边是详情：轮次、令牌、模型、目录、创建时间、来源、首条消息，以及「在 Codex 打开」；
- 列表逐行错峰淡入；选中时左边那条竖杠从上一行滑到这一行——背景色说明"现在选的
  是谁"，滑动的竖杠说明"选择变了"，两件事分开画才不会互相盖住；
- 读库的几十毫秒里显示骨架屏，右边写"正在读取"，而不是留一张白纸；
- 900 多条一次只画 50 条，底部写「还有 N 条 · 继续加载」；
- 进页面自动读一次，库文件变过才重读（一次 `stat` 就能判断）。

## 2.11 做了什么

2.11 只做一件事：**把"它在干什么"画清楚**。以前认出来和还在找长得一模一样，用户没法判断它是卡住了还是正在算。

- **扫描和锁定分成两种视觉**。扫描是"淡角标 + 一道来回扫的光带 + 转圈的标签"，锁定是"角标从外面收拢 + 落定闪一下 + 标签浮出"。混成一种的话，一个静止的框说明不了任何事：是在找，还是已经认准了？
- **落定那一下要有回执**。角标亮到发白、外面推开一圈亮边，0.34 秒收工。只有"新认出来"才闪，换目标不闪——闪得太勤就不叫回执了。
- **进度卡贴着当前那个框**。固定在顶上会和应用的标题栏、菜单撞在一起，固定在底下会压住输入框。贴着正在处理的框放，卡片说的是谁一眼就对得上；再拉一根细线连过去。卡片本身也带信息：第几步 / 共几步、带刻度的进度条、左侧一条按状态变色的色条。
- **发送按钮这种小方块要跟着外层走**。它套在输入框里、还贴着窗口右下角，卡片跟着它就会被挤到角上、压在输入框上。现在先找"包住它的那个框"，再按那个框定位。
- **小图标的标签放旁边**。图标只有几十像素，标签压上去等于把它盖掉。
- **失败也要留回执**。卡片变红、写明为什么停，停一下再撤浮层。
- **浮层不能污染自己的校验**。这一条是真踩出来的：浮层画在目标窗口上方，截屏会把它一起截进来，角标收拢、落定闪、点击涟漪都会让"像素变了"成立。现在取基线之前、开始比对之前都先等这段动画过去。不做这件事，"粘贴校验"和"发送校验"会把自己的动画当成应用的响应。
- **扫描区域用屏幕坐标**。第一版把客户区坐标当屏幕坐标传进去，整个扫描区偏出窗口左上角，标签只剩一条边——看起来像识别错了，其实只是坐标系错了。

## 2.10 做了什么

2.10 解决三件事：**窗口多大都能认**、**只走搜索这一条链路**、**认不出来时不许乱点**。

- **几何全部按比例算，不写死像素**。侧边栏右边界、面板中心、标题栏高度都从画面里量。1200×900 到 3840×2115 五个尺寸逐个验过，切换对话 10/10 全通。也可以锁定某个窗口句柄，或者指定尺寸强制窗口大小。
- **只走搜索，不滚列表**。列表会折叠、会分组、会随历史无限变长，翻列表既慢又永远翻不完；搜索不依赖应用当前停在哪。
- **面板框不能框成整个窗口**。三个原因分别修掉：按"同一列对齐"认面板会把侧边栏也算进去（这一档删了）；同一 `top` 上的正文会被并进筛选标签那一行（改成按横向间隔断链）；输入框按"这一列最靠上的一行"取会取到结果行（改成先按排版**推**一个横带，再拿识别到的字去**校**）。
- **OCR 会把中文整段丢掉**。搜「PDF 渲染与 DOCX 处理」，读回来的是 `PDF DOCX`——词确实进去了，结果也出来了，但按整串比永远对不上，于是被当成"没粘进去"。现在按"按顺序能对上多少个字"算（LCS），并多留一档"允许丢几个字"的匹配。
- **发送位置有三种图标**：发送箭头、麦克风（输入框空着）、暂停（正在生成）。以前把麦克风认成暂停，`stop_generation` 点下去弹出了「Voice chat couldn't start」。现在按"这一行有几段墨迹"区分三态，并且发送前加了一道守卫：位置上是麦克风就停下，绝不点。
- **占位符读不到时不能判成"没发出去"**。灰色占位符 OCR 经常整个读不到，于是明明发出去了也判失败、再按一次 Enter。现在的判据是"我们刚粘进去的那段字还在不在"——发出去了就一定不在了。
- **容错是一条阶梯，每一级都要有判据**：放大镜 → Ctrl+K → 再点一次 → 按几何位置兜底。每一级都以"面板自己的东西出现了"为准，而不是"点过了就算打开"。

## 2.9 做了什么

2.9 只做一件事：切对话的兜底路径改成**放大镜搜索**，并且每一步都看得见。

以前列表里翻不到就放弃了。列表翻不到是常态——历史长了、对话折在项目分组里、或者它压根不在侧边栏的第一层。搜索是唯一的正解，而且 Codex 桌面版本来就有一个放大镜。

链路固定成五步，每一步都截图核对过，不靠猜：

1. **找放大镜**：标题栏里从左到右是「Codex ⌄」、铃铛、放大镜。先找出侧边栏的右边界，再在这一段里找图标大小的墨迹块，最右边那个就是它。框住，点。
2. **认面板**：面板浮在窗口正中，最上面是输入框，中间是结果，最下面是 `All / Actions / Chats / Files / Text` 那排筛选标签。输入框是"贴着面板左边缘那一列里最靠上的一行字"，框住。
3. **输关键词**：点输入框靠左的位置（不点正中），全选，把标题粘进去。
4. **认结果**：只在「Chats」分组里找，别的分组一律不看。框住。
5. **点开、核对**：点结果行，再读一次消息区顶部的标题，对上了才算切换成功。

这一版踩到并修掉的坑，都是真实画面逼出来的：

- **搜索结果不止有对话**。面板是分组的：命令在「Quick actions」下，对话在「Chats」下，文件在「Files」「Recent files」下。搜 `20261107` 时面板同时给出一个对话和四个 `2026-11-07-liquid-glass-*.md`。按文字相似度挑，`2026-11-07-liquid-glass-c52.md` 和标题 `2026-11-07-liquid-glass-c52` 几乎一样——挑中它点下去打开的是文件。现在先定出「Chats」分组的上边界和下一个分组标题的下边界，只在这个区间里找；区间里没有就明确报「不是一个对话」，绝不退而求其次去点文件。
- **一行不等于一条识别结果**。OCR 会把长标题拆成两段（`0 20261107` + `32 Big LiquidGlass`），右边还会多认出一段项目名。现在先把同一纵向位置的文字归并成"行"，再按"从左边开始的前几段"逐个比，取最像的那个——右边的项目名拼进去只会把相似度拉低。
- **面板底部那排筛选标签里也有一个「Chats」**。认错它，"输入框"会被算到面板最下面（y≈1335）。现在分组标题只在上半部分找，标签则靠"同一行至少三个标签"来认。
- **加载中和没结果时，一个分组标题都没有**。这时候靠底部那排标签认面板——面板一打开它就在。没有它就只能认定面板没开，然后去点放大镜，反而把面板关掉。
- **放大镜不能按窗口高度算位置**。菜单栏和标题栏都是固定像素高，窗口从 3840×2115 缩到 2560×1410 时，按比例算出来的那条带正好落在菜单栏和标题栏之间的空白上，一个图标都扫不到。改成固定范围，扫不到再用 OCR 认「Codex」——它和图标在同一行。
- **分组标题不能只做前缀匹配**。`Chat` 这个标题会把正文里的「ChatGPT can edit any file...」也算进去，于是"输入框"被算到窗口底部，点下去反而把面板关掉了。现在只认「Quick actions」「Chats」「Recent files」，标题后面最多容忍两个字符（OCR 会把 `Chats` 读成 `Chats O`）。
- **结果行不能跑出面板**。对话正文里完全可能出现一行字就叫 `20261021 18`（x=1677），面板里的结果在 x=1368；左边那一栏的对话列表里更是有一模一样的一行（x=102）。两个方向都要卡住：横向只认面板那一列，纵向只认分组区间。
- **放大镜是开关，不是"打开"**。面板已经开着的时候再点一次会把它关掉。所以点之前先看一眼面板是不是已经开着。
- **浮层要先亮起来**。`box()` 和 `progress()` 在浮层不可见时是空操作，切对话发生在浮层显示之前，画的框会悄悄丢掉——用户只看到窗口自己动了几下。现在进 `_switch_conversation` 第一件事就是把浮层显示出来。
- **框完停一下再点**。框和点击几乎同时发生，不停这 0.3 秒，人眼看不到"它认的是哪一个元素"。

浮层上那行进度字也跟着走：`切换对话` → `打开搜索` → `输入关键词` → `选中结果`。

## 2.8 做了什么

2.7 解决"点了没反应"，2.8 解决"看不见就什么都做不了"。

起因是切对话时的一连串失败：侧边栏收着，列表区里只有图标，OCR 从图标上读出几个乱码字符当成对话标题；展开的快捷键按了没反应；窗口明明在前台，点击却落到别的程序上。逐个查下来，是四个各自独立的问题。

- **侧边栏收没收起，现在能判断了**：看 90~190 这一竖条里有没有文字，和窗口宽度无关。以前按"分隔线占宽度的比例"估，2560 宽的窗口估出 409，收起的侧边栏被当成展开的，于是拿一排图标去 OCR。
- **收起了就自己展开**：先按 `Ctrl+Shift+S`（Codex 桌面版 View 菜单里的「Toggle Sidebar」），再按 `Ctrl+B`（网页版认这个），最后才去点标题栏里那个方形开关。开关位置不写死——现场在标题栏里数图标，从左往右第三个就是它，窗口缩放比例变了也不会偏。每一条路都以"重新判断一次侧边栏状态"为准，确认真的展开了才算成功。
- **找对话不再数屏数**：以前固定翻 8 屏就放弃，历史长的账号永远找不到靠下的对话。现在只在"列表真的滚不动"时停，中途每 5 屏写一行日志，让人看见它还在找。
- **列表里折着的东西会点开**：侧边栏是按项目分组的，一个项目下超过五条就折成一行「Show more」——折叠着的那部分根本不在列表里，只滚不点永远找不到。翻到底还没有，就点开「Show more」再翻一遍，最多三轮，之后才去用搜索框。
- **切对话前先展开侧边栏**：收着的时候翻列表等于在图标上白翻，所以先展开；展不开就直接走搜索，不浪费一轮。
- **抢前台的兜底**：`SetForegroundWindow` 和 `SwitchToThisWindow` 在目标窗口刚被用户切走时都会返回 0 却什么都不做——表现是"程序说切换了，屏幕上没变"。现在多一步 `AttachThreadInput`：临时接到当前前台线程的输入队列上再抢，用完立刻断开。不注入任何按键，所以不会像早先那样把输入漏到别的程序里。
- **选窗口跳过辅助窗口**：Codex 常驻一个 1225×2115 的 `WS_EX_TOOLWINDOW`，有标题、比主窗口还大，用户看不见也点不进去。以前按面积排序会把它选中，之后每一步都在往空气里点。现在工具窗口排到最后，只剩工具窗口时按"没有窗口"处理。
- **看不见画面就先让它可见**：Chromium 被完全遮住时会停止出帧，`PrintWindow` 照样返回成功，但画出来是全黑。全黑时先把窗口提到最前面（`SWP_NOACTIVATE`，不动键盘焦点）再截一次。

## 2.7 做了什么

2.6 解决"窗口去哪儿了"，2.7 解决"点了没反应"。

起因是一次真实的报障：鼠标能动能点别处，就是点不动某个程序里的任何东西。查下来不是 CueRelay 的浮层——是另一个应用的一个窗口，`WS_EX_TOPMOST` 为真、`IsWindowVisible` 为真、屏幕上却什么都没画，而 `WindowFromPoint` 在整块屏幕上到处都命中它。DWM 认为它在最上面，于是每一次点击都先落到它身上。取消置顶之后，同一个点立刻落回下面那个程序。

- **应用页多了「窗口抢点击」**：点「检查」列出所有设了「总在最前」的窗口（排除任务栏、桌面、开始菜单这些外壳窗口，也排除 CueRelay 自己）。查出东西时按钮变成「全部取消置顶」，一键撤掉。
- **命令面板里有「排查窗口抢点击」**：鼠标点不动的时候，界面上的按钮也点不动——但 `Ctrl+Alt+K` 还能用，这是唯一的键盘入口。托盘菜单里也有同一条。
- **修复不只是取消置顶**：还要 `ShowWindow` 把被 DWM 遮蔽的窗口恢复出来、`InvalidateRect` + `RedrawWindow` 强制重绘。最后再"抖一下尺寸"——Chromium 只有收到尺寸变化才会重新布局，单纯让它重绘是没用的。最大化窗口跳过这一步，否则会把用户的工作区改掉。
- **窗口识别不再优先挑工具窗口**：`WS_EX_TOOLWINDOW` 的窗口通常是应用自己开的辅助面板（浮窗、取词条），同分时它排在后面。这次那个幽灵正好就是工具窗口。

## 2.6 做了什么

2.5 让它在系统里待得住（自启、热键），2.6 补上"待在哪里"：托盘。

- **托盘图标**：右键有菜单（显示主窗口、命令面板、启动/关闭 Codex、立即运行、暂停/恢复定时任务、退出），左键点一下或双击直接唤回窗口。鼠标悬停显示「CueRelay · 35 个任务 · 6 个启用」，执行中会多一段「执行中」。
- **暂停定时任务**：托盘菜单和命令面板里都有。暂停只拦"按时间自己触发"，手动执行和界面按钮照常；暂停期间到点的任务不会补跑，恢复后按错过执行处理——否则暂停一整夜、恢复瞬间会一口气全发出去。
- **关闭窗口的动作可以改**：收进托盘 / 最小化 / 每次询问 / 直接退出，四选一。默认收进托盘——定时任务靠它才跑得下去。
- **最小化时也收进托盘**：默认开，任务栏就不会被它占一格。想留着就关掉。
- **开机启动时不显示窗口**：配合开机自启，开机后只有托盘图标，不弹窗。
- **第一次收起时说一句**：气泡提示「CueRelay 仍在运行」，否则用户会以为程序被关掉了。同一个进程里只提示一次。
- **任务失败才弹气泡，而且只在收进托盘时**：窗口开着的时候界面上已经有红点了，再弹就是噪音。
- **任务跑完不会把窗口弹回来**：执行前窗口是自己藏起来的，执行后原本会 `deiconify`。用户主动收进托盘的，就让它留在托盘——否则看起来像程序自己跳出来了。
- **托盘起不来会直说**：通知区域没运行、或者系统拒绝注册时，开关拨回去，关闭动作退化成"每次询问"，不会留一个按了没反应的图标。

## 2.5 做了什么

2.4 把 Codex 的日常操作收进来了，2.5 收拾的是"这个工具在系统里怎么存在"：

- **开机自启**：设置里一个开关，写注册表的 Run 项，用 `pythonw.exe` 起，开机后没有多余的控制台窗口。写不进去（组策略、权限）会把开关拨回去并说明原因。
- **全局热键 Ctrl+Alt+K**：在别的程序里按一下，CueRelay 回到前台并直接打开命令面板——不用先去任务栏找窗口，再按一次 Ctrl+K。
- **执行期间热键不响应**：动作执行时窗口是自己藏起来的，这时把窗口叫出来会正好盖住目标窗口上要点的位置。宁可不响应，也不要在自动化中途插一杠，日志里会留一行说明。
- **热键注册失败会直说**：组合键被别的程序占用时，开关会拨回去并提示原因，而不是显示"已启用"却按下去毫无反应。
- **提示词变量**：`{{date}}` `{{time}}` `{{datetime}}` `{{weekday}}` `{{clipboard}}`。定时任务里的 `{{date}}` 展开的是"执行那天"，不是保存任务那天——否则每天发出去的都是同一天。片段里同样可用。
- **命令面板改成窗口里的一层**：以前它是独立的置顶窗口，主窗口自己置顶时，第二次打开会落到主窗口后面、背景也画不出来——按 Ctrl+K 看起来毫无反应，其实键盘已经被它抢走了。现在它只是主窗口里的一个覆盖层，没有 z-order，也没有跨窗口焦点。

## 2.4 做了什么

2.3 之前它是个「定时发提示词」的工具。2.4 把 Codex 日常要做的几件事都收进来，做成一个工具箱：

- **片段库**：常用提示词存起来，按使用次数排序，一键发送或变成任务。以前每次都要把同一段话再粘一遍。
- **对话导航**：读侧边栏，把对话标题列出来，点一条切过去。侧边栏收起时先用 Ctrl+B 试着展开，展开不了就明确说「侧边栏是收起的」，而不是把图标上的乱码当成对话列出来。
- **命令面板（Ctrl+K）**：一个输入框加一列结果，视图、任务、片段、对话、应用开关全在里面。界面上能点的东西都能打出来。
- **执行记录**：每次执行都留一条（成功与否、耗时、错误、第几次重试），日志页多了一个「执行记录」页签。
- **失败重试**：任务可以设重试次数与间隔。只重试「还没把内容交出去」的失败——已经点过发送再重来一遍，结果是同一个提示词发出去两次，那比失败更糟。
- **几个快捷动作**：停止生成（只在那个位置真的是暂停键时才点）、清空输入框、新建对话。它们和定时任务共用同一把窗口锁，不会同时去点同一个窗口。

顺手修掉的 bug：

- **分隔线识别会越界**：`detect_panels` 比较 `row[x + 2]`，但整行只取到 `width - 2`。全黑画面时 `and` 短路把越界掩盖住了，一旦窗口右边缘附近真有一条亮线就抛 `IndexError`——表现是窗口一拉宽，输入框识别就整个失效。
- **「在后台」的判断把遮蔽窗口算成可见**：被 DWM 遮蔽的窗口（收进托盘、在别的虚拟桌面）`IsWindowVisible` 依然为真、矩形也正常，但屏幕上根本没有它。现在按隐藏处理，并且切前台之后会再确认一次它真的在屏幕上。
- **定时器无限累积**：应用页的状态轮询每轮都往 `_after_ids` 里追加一个 id，跑一整天就是几万条永远不会被取消的字符串。现在只保留一个。
- **手改配置的布尔值**：`"false"` 在 Python 里是非空字符串，等于真。现在所有布尔设置统一纠正。
- **片段搜索收不到粘贴**：从 `<KeyRelease>` 改成 `trace`，和任务搜索一致。

## 2.3 做了什么

2.2 让任务列表能管了，2.3 管的是任务之外的那半件事——**在执行之前，目标应用得先在那儿**：

- **新增「应用」页**：Codex 与 v2rayN 各一张卡，实时显示「运行中 / 在后台 / 未运行」，右边是启动与关闭，下面是一键启动和两个建定时任务的按钮。状态每 2.5 秒刷一次，用户自己关掉或从托盘恢复都会跟上。
- **执行前自动拉起目标应用**：以前窗口没开就直接报错「没有找到目标窗口」。现在会先把它拉起来再发，收进托盘的走恢复而不是重启（0.04 秒 vs 2.8 秒）。
- **在 CueRelay 里开关 Codex**：启动走 AUMID，关闭走 `WM_CLOSE` + 终止进程，都是真开真关，不留在托盘。
- **自动检测并绑定 v2rayN**：启动时找一次，找到了写进设置并记一行日志；设置页有「自动检测」和「打开所在文件夹」，路径也可以手填。
- **定时开关 Codex**：任务类型多了「启动应用 / 关闭应用」，可以像普通任务一样按单次 / 每天 / 间隔排。启动类任务会先确保代理再前置窗口。
- **执行前的窗口判定更保守**：恢复失败时返回失败，而不是顺手启动一个新实例——那会开出两个一模一样的窗口，之后认哪一个都可能认错。

## 2.2 做了什么

2.1 解决了「认得出屏幕」，2.2 收拾的是「认出来之后怎么管」——三十多个任务堆在一个列表里，打开就是一大片同名旧任务，这跟识别准不准没关系：

- **分组可折叠，「已停止」默认收起**：列表按「进行中 / 失败 / 已停止」分组，点分组标题展开或收起。做完的任务留在那里但不再抢位置，失败的那一组仍然默认展开。
- **打开就落在真实任务上**：以前首屏是一张空的「新建任务」表单，看不出这个工具在做什么；现在自动选中第一个任务，名称、提示词、计划、发送方式、目标对话一次全在屏幕上。
- **失败的行不再重复写一遍「失败」**：分组名和红点已经说明了，右侧改成失败发生的时间；没有执行记录的老任务就留空。
- **去掉重复的任务数量**：以前列表表头和底部状态栏各显示一次，现在只在表头。
- **没有计划时间的任务回填 5 分钟后**：已完成、失败、暂停的任务本来就没有下次执行时间，以前回填「现在」，用户一保存就会被问「时间已经过去，是否立即执行」。
- **发送位置会换图标**：输入框有内容时是发送箭头，正在生成回答时是暂停键，空的时候是麦克风。三种状态的外壳尺寸和填充率完全一样，只看外壳会把暂停键当成发送按钮点下去，把正在生成的回答掐断。现在先确认输入框里真的有内容（占位符没有回来），再看方块里的字形是「人字 + 竖杆」还是「两根竖条」；是暂停就等它变回箭头，等不到就放弃这次发送，而不是盲点。

## 2.1 做了什么

2.0 把定位方式从手动坐标换成了像素识别，但像素只能回答「这里像不像一块面板」。2.1 补上了「屏幕上写着什么」：

- **读屏**：调用 Windows 自带的 OCR（`Windows.Media.Ocr`，中英文识别包随系统语言安装），把界面文字连同坐标一起读出来。Python 侧不引入任何第三方库，识别交给一个常驻的 PowerShell 进程，单次约 100ms。系统没有可用识别包时自动退化为纯像素识别，功能不受影响。
- **对话切换不再依赖搜索框**：直接在侧边栏列表里按标题找到那一行，点它，再用消息区顶部的会话名确认切换成功。列表里没有就回到顶部再一屏一屏往下翻。搜索框（Ctrl+K 或放大镜）只作为兜底。
- **标题比对是严格的**：只认「完全一致」或「一方完整包含另一方」。`Helloalp Read 20261012 1` 和 `Helloalp Read 20261010 1` 只差两个数字，字符相似度高达 0.90，用模糊匹配会把消息发进隔壁对话。
- **输入框定位多了一条可靠路径**：先找占位符文字（`Work with Codex` / `Ask anything` …），从一个确定属于输入框的像素向外扩出整块面板；输入框里已经有内容时，改用窗口底部最靠下的那段文字当锚点。像素面板识别退为第二条路。
- **发送按钮排除麦克风**：按钮必须是接近正圆、内部被填满的色块。之前识别出的输入框比实际矮一点，按钮下半截被切掉，于是选中了左边的麦克风，一点就开始录音。
- **发送成功的判据改成「占位符回来了」**：像素「变了」靠不住——点错按钮、弹出提示、开始录音都会让输入框变化。

## 识别与校准

- 执行时优先实时识别。设置里的「执行时重新识别界面」关闭后，才会直接使用保存的位置。
- 「校验粘贴结果」「校验发送结果」默认开启。关闭后执行更快，但失败时不会报错。
- 「对话切换失败时中止」默认开启。关闭后，找不到目标对话时会直接在当前对话发送。
- 自动识别失败常见原因：目标窗口被别的窗口遮挡、窗口处于最小化、目标应用还没渲染完成。识别会重试，但遮挡是截不到内容的，执行前请让目标窗口可见。
- 如果对话名确实不存在、或它被折在一个没有展开的项目分组里，切换会失败。开启「对话切换失败时中止」可以避免消息发到错误的对话。

## 第一次使用

1. 打开目标应用（默认关键词 `codex, chatgpt, openai`，可在设置里改），进入要发送提示词的会话。
2. 启动 CueRelay，进入「应用」，确认 Codex 与 v2rayN 的状态和路径。v2rayN 通常已经自动绑定，没有就点「重新检测」或去设置里手填。
3. 进入「设置」，点击「自动识别并预览」。窗口会暂时隐藏，随后弹出识别结果：截图上会用方框标出输入框、发送按钮和对话搜索框。确认无误后点「保存」。
4. 回到「任务」，填写名称与提示词，选择计划方式，点「保存」。
5. 需要立刻验证时点「立即执行」。
6. 如果这句话以后还会用到，去「片段」页新建一条，下次一键发。

想看看有哪些对话，去「对话」页点「扫描对话」。之后按 Ctrl+K 就能用标题直接跳过去。

如果预览里框错了，点「重新识别」；如果某个位置始终识别不到，可以在「识别与校准」里用「手动指定」按 F8 记录一次坐标作为兜底。

第 1 步也可以省掉：设置里「执行前自动拉起目标应用」默认开启，执行时会自己把 Codex 拉起来。第一次用仍建议先手动开一次，确认登录状态正常。

## 运行行为

- 窗口默认置顶，可在标题栏或设置里关闭。
- 默认收进托盘而不是退出：点关闭、点最小化都只是把窗口收起来，定时任务照常执行。托盘图标右键有菜单，左键唤回窗口。这套行为在设置 → 托盘与关闭里可以改。
- 可以在设置里让 CueRelay 随开机启动，此时它只留一个主窗口，不弹控制台；再打开「开机启动时不显示窗口」就只留托盘图标。
- 全局热键默认开启（Ctrl+Alt+K）。正在执行任务或动作时按它不会唤出窗口，只在日志里记一行。
- 执行时会暂时隐藏自身，避免挡住目标窗口，完成后恢复。
- 默认在执行前恢复校准时的窗口位置和大小，可在设置里关闭。
- 执行前会先把目标应用拉到前台：没开就启动，收进托盘就恢复（见「应用与代理」）。
- 执行前会确认目标窗口是前台窗口，不是就停止，不会向其它程序输入。
- 粘贴与发送之间会重新识别一次输入框，以适配多行内容导致的输入框变高。
- 程序会尽量恢复执行前的文本剪贴板，并把鼠标移回执行前的位置。
- 同一时刻只允许一个任务驱动鼠标键盘，避免多个任务抢占窗口。
- 步骤间隔只影响固定等待，识别与校验使用自适应轮询，不受该值限制。
- 错过执行时间超过「补执行窗口」就跳过本次；单次任务会标记为已过期，重复任务会推进到下一次计划。
- 失败重试只针对「还没点发送」的失败。内容已经提交过就不再重试，避免同一个提示词发两遍。
- 暂停定时任务后，按时间触发的任务都不再执行，手动执行不受影响。恢复时按「补执行窗口」判断：暂停期间错过的那些不会被一次性补发。
- 任务与设置保存在 `cuerelay_data.json`，运行日志在 `cuerelay.log`，未处理错误在 `cuerelay_crash.log`。
- 从 1.x 升级时，旧文件会自动迁移，并保留一份 `cuerelay_data.v1.json` 备份。旧版本的手动锚点会按窗口坐标继续生效。

## 数据

任务字段：类型（发送提示词 / 启动应用 / 关闭应用）、名称、提示词、目标对话、计划方式（单次 / 每天 / 间隔）、发送方式（点击发送 / Enter 发送）、失败重试次数与间隔、启用状态。开关类任务不需要提示词、发送方式和目标对话。

片段字段：名称、内容、使用次数。名称为空时取内容开头，列表里至少认得出是哪一条。

提示词和片段里都可以写变量：`{{date}}`（2026-11-07）、`{{time}}`（09:05）、`{{datetime}}`、`{{weekday}}`（周六）、`{{clipboard}}`（执行时的剪贴板内容）。它们在内容进剪贴板之前才展开，认不出的占位符原样保留，不会被替换成空白。

执行记录：任务名、类型、成功与否、耗时、错误信息、第几次重试，最多保留最近 200 条。

设置里另有：目标应用关键词与路径、Codex 的 AUMID、v2rayN 路径、「启动 Codex 前先确保 v2rayN 已运行」、「执行前自动拉起目标应用」、「全局热键」开关、「显示托盘图标」、「关闭窗口时」（收进托盘 / 最小化 / 每次询问 / 直接退出）、「最小化时也收进托盘」、「开机启动时不显示窗口」。

开机自启不写在数据文件里，它就是注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `CueRelay` 一项，删掉这一项等于关掉。这样即使数据文件被删，开关显示的状态也不会跟系统对不上。

日志页可按级别筛选，并直接打开日志文件。
